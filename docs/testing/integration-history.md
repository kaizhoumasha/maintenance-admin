# 统一对接历史软件验证记录

本记录仅证明隔离开发环境中的软件行为。未执行生产停写、现场切换或设备验收；旧写入者库存、生产数据规模和实际维护窗口仍需现场证据。

## 制品 A 的边界

制品 A 的迁移 head 为 `integrationhistoryauthority`，包含 expand / authority，不包含 contract。独立源码归档及逐文件 SHA-256 清单保存在该计划的本地验证目录；归档必须先于制品 B，不能用后来含 contract 的工作区执行 A 的默认 upgrade head。未构建、推送或部署生产镜像。

最初 A1 候选已因 CORE 原文借用与到期清理的并发缺口作废，原归档保留供追溯。后续 A2 候选完成独立软件验证后，又在补充回归中暴露只收到 HTTP 状态而没有正文时的交付结论保存问题，已由 A3 修正。独立全分支审查随后补齐旧无正文结论的权威校验、活跃期结果采用、准备引用和 SQL 描述一致性，形成 A4。A4 沿原 A1 / A2 / A3 归档补入共享证据引用锁、已清理原文拒绝、缺少正文的结论关联、模型默认 ID 延迟导入及对应回归，仍停在 authority；不能用制品 B 的最终 ORM 覆盖 A 侧。提交前审查再修正租约恢复的旧响应指针并补齐反向查询访问路径，形成 A5；运输补录的原身份匹配与两阶段证明再经提交前审查修正后形成 A6 / B2；本轮事件名称兼容修复后另行冻结 A7，不覆盖此前的原归档。各候选的软件验证与归档校验分别留存，只有最终清单指定的归档可作为构建输入。

## 代表性 PostgreSQL 测量

本机隔离 PostgreSQL 17 / Redis 8；单客户端、热缓存、无其他业务负载。这是观测值，不是生产 SLA 或峰值吞吐保证。保存的 EXPLAIN 使用 ANALYZE / BUFFERS / JSON；查询计划原件与测试日志位于本计划验证目录。

数据：2,001 个交互，其中 100 个在 90 天窗口内、1,900 个普通实例在窗口外，另一个受保护 ECS 原命令；20,000 条诊断，两个根各 10,000 条，正文合计 20,480,000 字节。另有 106 个同时间/跨窗口实例、每根15个引用的分页测试。

| 项目 | 修正前 | 修正后 |
| --- | ---: | ---: |
| 20 条摘要的 SQL 次数 | 4 | 4 |
| 100 条摘要的 SQL 次数 | 4 | 4 |
| 20 条摘要，会话总耗时 | 15.84 ms | 13.04 ms |
| 100 条摘要，会话总耗时 | 9.64 ms | 5.14 ms |
| 原 Result 查询 | 1 SQL / 4.19 ms | 1 SQL / 2.57 ms |
| 清理 1,900 个过期根，批次100 | 46.21 s | 26.19 s |
| 证据表含索引物理大小 | 33,382,400 B | 33,480,704 B |
| 其中索引大小 | 6,037,504 B | 6,135,808 B |

清理前每个负向证据引用探针过滤 20,000 行；三个非空反向索引后使用定向 Index Scan，未匹配探针不遍历诊断历史。普通历史删除将根的证据 ID 集留在 SQL 内，比较锁定数量后再删除，避免把长时间线展开为数万个参数。单根删除仍在一个事务内保证引用完整性；批次按根限量，因此真实超大单根的维护锁时长须在站点副本再次测量。ECS 命令与核心 Result 不参与普通摘要自动删除。

原 Result 读取走 exchange 原身份和 result semantic_digest 定向索引，不读取诊断正文。摘要/时间线显式选列，权限允许取正文时才装配 bytes。所有测量计划无临时文件读写；排序与扫描细节保留在 JSON，不承诺其他数据分布使用相同计划。空的运行表出现 Seq Scan 是空表优化选择，尚不能证明有大量在途数据时的性能。

5,000 条保留诊断下，PostgreSQL 原 gate 18.41 ms、finish 19.65 ms、Result 含提交40.83 ms；SQLite 对照4.55 /7.71 /17.58 ms。这些数值采于新增 CORE 引用保护之前，未重新测量该保护的额外成本；没有竞争锁等待，不能作为并发锁延迟指标；业务先/清理先、原工作线全局锁序和引用提交交错另由真实 PG 并发用例验证。

容量预算必须包括旧新并存、仍受保护的长期存量、索引、WAL、备份和归档。上述大小来自实测物理存储，不能据此许诺未知原文的压缩率。生产补录批次耗时、WAL 峰值、备份窗口和混合在途分布尚需真实副本测量，开发的小样本补录用例仅证明可恢复/幂等/拒绝冲突。

## 软件贯通与边界

正式 coarse-sorting 装配在独立 PostgreSQL 数据库及 SQLite 中经过三个实际子进程：原扫描受理、WMS 判定、ECS 受控 HTTP、原 Result、运输回调、业务消费、配置阻塞后进程重启恢复。另有原 ECS loopback 的 ACK/Result 顺序、UNKNOWN/HELD 不换号自动重发、原 lease 结论和真实清理后长期重放测试。测试对端为本地受控模拟，不代表供应商或设备验收。

回填验证包括全部八来源、重复执行/检查点丢失、可变来源最终重扫、冻结字节与指针校验、原整数序列高水位、未知 writer 拒绝、原在途发送门禁、旧快照预览与缺失区分。只有真实维护窗口的 writer 库存和最终报告可授权现场启用；测试里的 DRAINED 不代表生产已排空。

SQL 管理查询可使用 `integration_exchange_summary` 与 `integration_record_summary`：显式无正文列，交付、协议、应用及 coverage 分开；运行关联不唯一时不会任取一行或使交互分页倍增。协议准备回复保存安全 code，原文到期后仍保留；旧可靠消息的尝试计数与状态保存在 LEGACY_SNAPSHOT 元数据中，不虚构旧逐次发送。

## 提交前增量验证

独立审查发现原租约恢复清空状态码和判定后，仍保留上次尝试的响应引用。SQLite / PostgreSQL × 主动释放 / 到期恢复四项回归先失败，清空 `last_response_record_id` 后15项租约测试通过；旧响应字节继续作为历史证据保留。另补充撤销历史查询权限后三个摘要接口均返回403的HTTP回归。

以每主表20,000行、20,002条证据的隔离PostgreSQL临时表复核真实查询形状，补齐13个交互、运行和关联反向索引。详情关联不能只添加反向索引，还需要独立的 `integration_reference.exchange_id` 索引支持完整OR条件。整根清理的 `OR / IN(子查询)` 即使有索引仍扫描整表，改用逐列分支的 `UNION ALL / LIMIT 1`，不把长时间线展开成Python参数，不增加往返、不改变原业务锁与重读规则。

代表性负向检查：交互引用从2.908ms /1,548块降到0.069ms /21块，消息引用从2.752ms /1,435块降到0.068ms /21块，运输引用从2.765ms降到0.043ms /14块。五类探针的未命中、外部命中和排除自身共15项结果等价检查通过。新增索引在样本上合计约4.27MiB；查询计划及样本分布另存验证目录。临时表使用本地缓冲，数据均匀且无业务竞争，不能推导生产时延、写放大、WAL或索引构建窗口；500个ID的低选择性查询仍可能使用顺序扫描。

此处增量证据不补足前述CORE保护后的可比 gate / finish / Result 及竞争锁时延测量，成本验收仍为 PARTIAL。最终完整测试与当前审查结果以本次PR的验证记录为准；没有项目开发服务时跳过浏览器验收，不使用其他项目的本机端口冒充本项目服务。

运输补录现在按原提交操作、operation_id和运输任务业务键核对原消息，已有接纳证明时核对记录的消息ID与目标。多个无法裁定的候选、错误既有绑定和矛盾证明均拒绝；原消息已清理时保留独立运输历史，收缩阶段仅在原规范请求可核对时沿原交互恢复。补录、authority及contract复用冻结的原身份校验，不再按编号取第一行。

完整测试增加可选的六道按文件分配，保持原断言、后端和超时；每道使用独立运行/迁移数据库及Redis。默认 `uv run pytest` 仍执行完整套件。分配与隔离见[并行测试](test-lanes.md)，实际耗时以完整运行的JUnit和日志为准，不能从分组数推导速度保证。

本轮 PostgreSQL 迁移证明用例改为每例独立临时源库，初始迁移及断言失败也回收；配置 URL 安全校验、项目 search_path 和 SQLite 模板缓存保留。此前两个门禁拒绝与后续 autovacuum 观察的因果关系尚未完全证实，未放宽生产门禁，见[测试隔离](test-lanes.md#独立存储)。

事件名称兼容修复由四项 HTTP 回归验证：NUL / 正常中文 × SQLite / PostgreSQL，先有2失败、2通过，修复后4通过（0.79秒），并纳入本轮全套。未注册事件仍 ACK，只有含 NUL 的可选 message_type 投影为空；原请求字节、摘要、诊断和先查重顺序不变，普通中文保留原值，非法代理字符仍沿原 Pydantic 校验返回400。

本轮主审及独立本机全分支零修改复审均未确认剩余 P1 / P2 / P3。分组覆盖评估为25/30（83%），是有上限的路径组证据评估，不是实测行或分支覆盖率；两组元数据、正文及引用的直接负例仍缺，另三组为真实对端/设备串联、现场 A→B 交接及生产容量/恢复验收。外部 Claude CLI 不存在，未完成跨模型审查。真实 broker 与独立 worker/Beat 的重启串联、实际部署写入者排空和 A/B 交接仍待验证；最终 CORE 保护后的可比时延与竞争锁成本仍未补齐，保留 PARTIAL。
