# 并行测试分道

完整测试仍使用 `uv run pytest`。不传 `--test-lane` 时，收集范围和执行顺序保持不变。
CI 将完整收集结果分到六个独立任务，各任务继续运行 Ruff 和所属测试：

```sh
uv run pytest --test-lane=1/6 -ra --durations=30 --junitxml=test-results.xml
```

其余任务把 `1/6` 改为 `2/6` 至 `6/6`，六个任务全部通过才算完整验证通过。
`N/T` 要求 `1 <= N <= T`；非法参数在执行测试前失败。

## 分配规则

分配来自本次实际收集的测试，不维护静态文件清单。新增文件和参数化用例会自动参与。
每个文件只分到一道，保留文件内及该道原有收集顺序，以继续复用模块级数据库与会话级空库模板。
所有道必须使用同一代码版本、依赖、收集参数及总道数；单独收集某个目录会得到该目录自己的分配。

`tests/lane_partition.py` 按文件汇总用例与夹具的相对准备成本，优先分配成本高的文件，
再放入当前估算负载最低的一道；同成本按路径、道号固定排序，因此不依赖输入收集顺序。
迁移、独立数据库、业务夹具和进程测试比纯校验用例权重高。
这些权重是准备成本估计，不是耗时承诺；用实际 JUnit 和 `--durations` 结果评估后再调整。

可先做只读收集检查：

```sh
uv run pytest --collect-only -q
uv run pytest --collect-only -q --test-lane=1/6
```

分道以 pytest 的 deselected 机制报告其他道的用例，不改动任何测试的跳过条件、超时或断言。
应合并六道结果，确认原完整收集中的每个 node ID 恰好出现一次，并核对实际跳过原因。

## 独立存储

每道需要独立的 `TEST_DATABASE_URL` 与 `TEST_REDIS_URL`。本地并行进程不能共用运行库；
部分回调夹具会清理整个相关运行表，单靠不同 schema 或 pytest 临时目录不足以隔离。
显式配置的迁移库也必须按道独立，且与该道运行库不同；未配置的旧可选后端仍按原合同跳过。

CI 的每个矩阵任务有自己的 PostgreSQL 和 Redis 服务，因此任务之间可以使用相同库名和 Redis DB 号。
在该任务服务内额外创建两个空库，分别配置：

- `TEST_HISTORY_MIGRATION_DATABASE_URL`：执行本次历史改造的 PostgreSQL 补录与迁移证明。
- `TRANSPORT_OWNER_MIGRATION_DATABASE_URL`：执行相关 Transport 原归属与位置证据迁移回归。

这两组验证此前未被 CI 显式配置；本次保留其独立临时库约束并启用它们，避免仅通过 SQLite 就交付历史权威切换。
CI 使用现有 `migration_database_ddl` 创建任务自有数据库，服务随任务销毁；不连接业务数据库。
其他旧迁移后端的配置与运行条件保持不变。

没有新增 pytest 插件或依赖。六道能减少串行等待，但实际收益受文件负载、数据库存储及可用 CPU 限制。
