# BIN_Roller Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development only after separate implementation authorization. Steps use checkbox (`- [ ]`) syntax for tracking。B1～B5 已按授权完成本地实现及分项验证；B6 文档边界核对已完成；B7 共享声明及隔离测试装配已完成，正式生产接入与整体验收未完成；组件及测试已随 [PR #42](https://github.com/kaizhoumasha/maintenance-admin/pull/42) 合入 develop（`e265ad7`），未部署。

**Goal:** 交付一个 BIN_Roller 组件处理完整滚筒箱流与五层架流，生产业务只提供任务/供箱/接续上下文及 SCAN2 业务接缝。

**Architecture:** 公共箱流只声明 bin_roller.COMPONENT，宿主可另组合 sorting_task 任务合同能力；SCAN1～4 唯一受理，SCAN2 先存事实再在原事务委托本业务，释放决定由业务给出、原放行由组件执行。普通/drain 共用一套内部架生命周期；架面、供箱及回流是内部方法，不是子组件。原业务仍只有一个 progression/scan_pending。

**Tech Stack:** 既有 ComponentDefinition/Capabilities、SQLAlchemy/Alembic、Pydantic、公开结果读口、Outbox/after_commit、pytest 与独立 PostgreSQL；不新增依赖。

**Spec:** [BIN_Roller 当前设计](../specs/2026-10-30-bin-roller-capability-design.md)、[C01～C07/R01](../../integrations/workline-bin-return-api.md)、[总计划/历史框架验收](2026-10-30-business-components-bin-roller.md)。旧进箱/回箱设计和 E/P3 计划索引已删除；阶段三只有 B1～B7，阶段一、二历史验收另存。

消费宿主划分已统一：smt_manual 承接 MANUAL 两方向，smt_auto 承接 AUTO 的 inbound/outbound；自动总计划由[S2接缝](2026-10-31-smt-auto-implementation.md#common-ports)、[S6装配/迁移/恢复](2026-10-31-smt-auto-implementation.md#common-runtime)各交付一份共同能力，S5统一释放/确认，I/O任务仅补方向行为，不分别创建上架/拣料组件或迁移。本计划公共状态、首宿主顺序与验收边界保持；方向合同及完成条件仍在统一自动API的对应分支。

## Global Constraints

- 一个业务只装配一份 bin_roller，不声明旧 bin_enter/bin_return COMPONENT 或外置架面服务；不嵌套组件，不建动态生产插件注册表。
- 组件及宿主不新增手工锁、资源预占控制、租约、协调版本锁、实时容量账；平台原事务/幂等/结果校验/发送保护保持。
- 新 ECS 动作沿导出的 PROTOCOL_RETRY_WINDOW=300 秒；原动作冻结期限不变。
- 原链后续执行由 ECS/物理在明确 callback Result 后推进；WES 不另建跨点前驱等待、执行对象令牌或 SCAN2 过期派发抑制；人工移出由独立 TODO 的维护端点剔除本次队列记录，不扩大正常流程。
- 原业务 owner、请求/命令/Transport 身份、字节/路由/期限/附录/历史 None 沿各协议已有语义保持，不迁移不存在的旧组件生产数据。
- 四点扫码事实直接保存；技术原身份幂等，本线本点连续相同业务扫码归原经过，有其他本点有效扫码/原 Result 则新进站；其他线/点位、ACK/心跳及重复 Result 不分隔。SCAN2 每经过只成功委托一次。
- 仅进入 BIN_Roller 架流/正常求架检查的原宿主单条独立 advance 在首 SQL 前设 PostgreSQL SERIALIZABLE，范围按设计 §7.1 覆盖表；既有统一入口整笔设置，不为细分 work 拆事务/另建入口或隔离选择器。复用原 session_factory 及包住外层 commit 的 40001 有界整事务重试；不升级 receiver、短扫描、既有无关纯生产或其他业务，不改共享引擎/连接池默认或新增执行器。内部方法用调用方 session，不提交/另开竞争事务/发 HTTP；独立单条推进/统一结果快照由原业务负责，结果只读公开端口。按设计 §7.1～7.3 用原经过/面服务/清单段序/周期动作及真实业务输入对应的单笔原意图登记，已有步骤先读原引用；同事务不替代业务唯一约束，不建通用父后继登记层或为制造冲突改写父记录。
- U01～U08 无首版待确认业务规则：U04/U05/U08 沿已验证 manual-picking 基线适配；明确不实施早到完工自动补绑、跨任务/跨普通-drain 目的留场复用，不留开关或占位接口。CTU03 接纳即释放，非离场沿现有 outcome/member_facts，B1/B7 只补身份正确且终位明确的目标/面向不符架位置，不复制正常/pending 结果，U06 为实现验收；不增加全线等待。
- 业务 fixture 表使用独立 MetaData 并 finally 清理；正式 MODEL_MODULES/迁移与真实消费业务同步，保持单一 Alembic head。
- 每项实现先 RED、最小实现、GREEN；测试断言公开可见的原意图/参数/归属及进度，不用私有函数调用次数代替生命周期行为。B1～B5 已有分项验证记录；B6 复用已通过的验证，不重复运行测试；B7 整体验收尚未完成。提交/部署/真实发送不随计划获准。

## Review Focus

- SCAN2 单输入目标、事实/业务委托同原事务；业务不准入与存储失败不同，原释放只作用原经过——B2/B7。
- 普通/drain 只有一处 rack_flow 生命周期实现，RACK_CYCLE 是定位/恢复入口之一；消费 FEED/RETURN_BATCH 等本次进度后，service 同事务进入同一实现，不等下一次 Beat 交接。DRAIN 只管供架批次/周期引用；首次面不重复 CTU02、下一面不重发 CTU01、面/批次/周期分别收口——B3/B5。
- 迟到上游不回退下游位置；CTU03 接纳即收原周期，不等最终 Result/位置；迟到终态只补历史、不清新架——B1/B5。
- 回箱结果确认成员已离开原交接来源时，仅撤销其原轮次已有放行动作的 SCAN4 当前投影；失败仍按原义务保留，新进站及其他箱不被旧结果清理；撤销与原批次消费同事务——B1/B4/B7。
- 取消后仍在制的段按原到位事实继续请求 WMS，未知请求恢复原身份；同任务新版本可原地续面；新需求不改写已登记换面或已开始的离场求值（含 WAIT/未知），跨任务/目的不自动接管——B3/B5。
- 正常回流唯一按 return_batch FIFO 推进；人工实际移出由独立 TODO 维护端点剔除对应队列记录，不为该例外增加冻结批次联动或 Sender 改造，也不作为正常流程启用前置——B4/B6。
- 重复回调、同/不同 work 的即时与 Beat 竞争、外层回滚及提交结果不明均按[恢复推演](../specs/2026-10-30-bin-roller-capability-design.md#roller-recovery-walkthrough)验原身份/业务唯一性；消费标记不替代待办收口，原通知丢失由持久关联恢复——B1～B5/B7；B6 不新增恢复设施。

固定本地数据与方法（接口目标，不是新增 wire）：

- CurrentTask(task_id:str|None, is_valid:bool)；宿主按原本地执行上下文提供有效性，上游取消不直接抹掉本地在制段；本地已结束/排队任务不当当前有效任务。
- SourceFaceRef(plan_revision:int, rack_id:str, rack_face:str)；精确原成员，面原样保留。
- SupplyChange(work_line_id:int, task_id:str, change_id:str, added:tuple[SourceFaceRef,...], withdrawn:tuple[SourceFaceRef,...])；change_id 关联业务已受理原消息，不新发外部 ID；重报原有效内容不重复需求。
- SupplyProgress(task_id:str, source:SourceFaceRef, feed_complete:bool, pending:bool, original_ids:tuple[str,...])；pending 包含原未决请求/完整清单/搬运及失败待处置，feed_complete 只按原成功/最终空清单；不由取消/技术闭合推导。`get_supply_progress(session,*,work_line_id:int,task_id:str)->tuple[SupplyProgress,...]` 返回原业务只读进度，不返回 ORM；空查询/缺关联不授予任务完成。生产业务用自己原来源引用及 SCAN2 arrival 查原义务，不等待全局 FIFO/架流结束。未开始撤销可返回 feed_complete=false/pending=false，须结合宿主原成员撤销事实结清，不要求补造投箱成功；已开始/原 pending 继续，缺预期关联不视为完成。DTO 不携带 withdrawn，宿主不直读组件表；人工映射见 [SMT 设计 §7.1](../specs/2026-10-31-smt-manual-business-design.md#smt-supply-completion)。
- SuccessorContext(state:str, evidence:dict)；state 仅 UNKNOWN/CHECKING/AVAILABLE/NONE，evidence 来自原业务准备/队列事实，不是占位或协调锁版本。
- Scan2Arrival(arrival_id:str, work_line_id:int, device_code:str, raw_bin_code:str, bin_code:str|None, scanned_at:int)；arrival_id 是本线本点事件流产生的持久本地经过关联，连续重报不刷新首次 scanned_at；分隔事件后的合法新消息形成新经过，完整旧消息身份始终技术幂等。
- 业务生产对象公开 async `read_current_task(session, *, work_line_id:int)->CurrentTask`、`read_successor(session, *, work_line_id:int)->SuccessorContext`、`accept_scan2(ctx, arrival:Scan2Arrival)->None`。工厂直接注入本业务对象，不创建通用策略引擎。read 方法使用本事务；accept 保存业务准入/生产状态及原意图，已有合法即时释放决定时可同事务调用组件唯一 release_scan2；不发 HTTP。组件不先套人工准入条件，也不对无任务扫码统一放行；各生产合同决定，普通不准入用状态表达而不回滚事实。
- BinRoller(context, capabilities, production) 公开 async `accept_scan(ctx,payload)->None`、`apply_supply_change(session,change:SupplyChange)->None`、`release_scan2(session,*,arrival_id:str)->str`（核对原关联，返回唯一原 command_code；不增加过期释放/无命令成功分支）、`get_scan2_release_result(session,*,arrival_id:str)->CommandView|None`。只读释放结果来自既有 ECS 公开 CommandView，不返回 ORM，不以缺失/ACK/pending=false 合成成功。
- RollerWorkRef(kind:str, record_id:str)；kind 仅 SCAN/SCAN2_RELEASE/FEED/RETURN_BATCH/RACK_CYCLE/DRAIN；SCAN4 成功且原回流仍待承接时，list_pending 必须继续从该原记录发现求架检查，不要求先存在 DRAIN/周期，不新增工作种类或调度表。原事实消费归属与统一推进按设计 §6.1 固定：唯一 rack_flow 实现登记 CTU/面转换；service 可从不同原 work 进入它，先由所属模块消费本次事实，再同事务保存下一原步骤/首个 Outbox 意图，不递归其他待办。DRAIN 只管供架/周期引用/收批；FEED/RETURN_BATCH 不复制架流决策，SCAN2 成功委托即收口受理项，生产 WAIT/完工归业务待办，SCAN2_RELEASE 只消费原命令。组件 `get_pending_upper_id(session,*,kind:str)->str|None` 读取本业务该类本轮最大记录 ID；`list_pending(session,*,kind:str,after_id:str|None,upper_id:str,limit:int)->tuple[RollerWorkRef,...]` 在该上界内按记录 ID 升序发现候选。原业务复用既有 coarse_sorting.scan_pending 的短会话上界/游标方式，生产与六类页面轮换；等待、无变化或单条失败也向后翻页，每轮结束丢弃游标，下次从头扫描，不增持久协调状态。ID 只用于遍历，不作物理先后/FIFO。`advance(session,work:RollerWorkRef)->str` 使用业务传入的独立单条事务；同一原记录不以不同 kind 重复投递同一职责，不给组件注入第二个 transaction runner。
- 内部 RackApplyResult(action_changed:bool, projection_update:str)，projection_update 为 UPDATED/HISTORY_ONLY/NEEDS_ASSOCIATION；`apply_rack_result(session,*,action_id:str,result:TransportTaskResult)->RackApplyResult`。非离场优先读现有 result.outcome/member_facts，只有目标/面向不符的明确架位置通过规划 result.position_observation 暴露原规范化 data/原 revision，不聚合正常/pending 结果；观察和动作履约分别处理；CTU03 读取原 submit 有效接纳即可收 WES 周期，不因 outcome 缺失或 closure 未 CLOSED 早退；action_changed=false 也要幂等检查原 pending 收尾，不重复新动作。
- 内部 `record_feed_success(session,*,feed_id:str,segment_id:str,result:TransportTaskResult)->str` 返回原机会引用；`record_return_outcome(session,*,service_id:str,opportunity_id:str,batch_id:str|None,reason:str,evidence:dict)->str` 只保存原批次结果/机会结束依据并返回原机会引用，不关闭面服务。WMS NO_BATCH/搬运结果必须显式给原 batch_id 并匹配原机会/请求/Transport；只有无外部批次的本地 NO_CANDIDATES/BUFFER_EMPTY 允许 None，不能用“本面最新批次”归属旧结果。该参数仅本地接口，不增加 wire 字段。kind=SEGMENT/FACE_END/PURE_RETURN；RETURN_SUCCEEDED 只直接结束段间机会，面末/纯回收一笔成功仅完成批次；NO_BATCH/NO_CANDIDATES 提供原机会结束依据，由唯一 rack_flow 实现核对本面原义务后结束面；BUFFER_EMPTY 仅记录可证明的真实排空，由原周期按 R01 收尾。
- 人工移出维护仅引用独立 TODO；本组件只识别本次回流已确认移出/退出队列的持久事实，不在当前计划新增维护查询接口或批次接管协议。
