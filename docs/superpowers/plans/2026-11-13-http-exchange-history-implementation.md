# HTTP 往来表实施计划

依据 [最终复审的设计](../specs/2026-11-13-http-exchange-history-design.md)。实现和验证使用独立工作区及可丢弃的本地数据库。

1. 为已开启的可靠发送保存按原租约定位的关闭事实。覆盖普通与冻结路由发送、恢复、释放、结算、暂停和范围停止。验证关闭随外层事务提交和回滚，未开启的租约保持零行。
2. 增加三张 HTTP 往来表，按原租约补写出站事实，按单次接收或同步调用保存入站及 Status。验证回调先结算、同步响应永远未到或迟到、提交后补写丢失、旧租约和新租约交错。
3. 迁移仍需的原权威证据，切换发送、回调、运行读口、清理及单编号排错。用隔离库验证对账失败使新写入保持关闭，并验证原有未知状态可以等价迁移。删除旧表另行验证准入。

当前工作区已加入往来采集、出站恢复补写和单编号查询。新运行表保留原收据 ID、原回执字节、ECS 裁决和留存锚点。Transport 保存原结果及触发收据 ID、提交接纳快照。旧的过程往来历史省略补迁。

启用独立运行证据需要先排空旧进程，再用 `alembic -x fence_legacy_writes=true upgrade http_exchange_query_views` 完成对账、锁止旧表写入并迁移查询视图。隔离库通过改名屏蔽三张旧表来检查重放、迟到响应、补写恢复、清理保护及查询。

启用 `INTEGRATION_RUNTIME_AUTHORITY` 后，旧历史接口与同名 SQL 视图从三张往来表及运行模型读取。兼容时间线由一次往来的请求、响应两侧构成，旧过程历史及其正文 UUID 省略补迁。单编号查询同时返回原运行状态。

删除是独立操作。核对联调验收、运行版本、可恢复备份和全部旧入口后，先在实际删除窗口运行 `python -m scripts.retire_http_exchange_legacy --evidence /path/to/evidence.json`。同一命令增加 `--apply` 时重新检查证据、旧表写入围栏、活动事务及外键和视图依赖。通过后以 `RESTRICT` 删除旧表，并在同一事务保存验收编号。联调数据库未参与本阶段。
