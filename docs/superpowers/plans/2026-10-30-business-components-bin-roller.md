# 业务组件框架与 BIN_Roller 分阶段 Implementation Plan

> **For agentic workers:** 后续按 superpowers:executing-plans 或 superpowers:subagent-driven-development 执行已获准任务。阶段一、二是历史已交付框架，当前仅重整文档，不写代码、不提交、不部署。保留原暂存及并行工作。

**Goal:** 复用已交付组件/原业务通知框架，接入一个 BIN_Roller 处理箱流与架流；生产业务提供任务、供箱、接续上下文和 SCAN2 作业决定。

**Architecture:** WORKLINE 只绑定业务，COMPONENTS 仅声明 bin_roller.COMPONENT；四点事件唯一进入组件，SCAN2 同事务委托生产业务，原放行由组件执行。组件内部只有一套普通/drain 架生命周期及原待办，不存在双组件交还或外置架面服务。

**Tech Stack:** 既有 Python/FastAPI/SQLAlchemy/Alembic/Celery、公开结果读口、Outbox/after_commit 与 pytest/独立 PostgreSQL；无新依赖。

**Spec:** [BIN_Roller 唯一设计](../specs/2026-10-30-bin-roller-capability-design.md)、[统一实施计划 B1～B7](2026-10-30-bin-roller-implementation.md)、[C01～C07/R01](../../integrations/workline-bin-return-api.md#return-pending)。

## Global Constraints

- 本轮仅文档，U01/U02/U03 和 ECS/物理推进按用户已确认规则，U04 沿已验证手工线适配、CTU03 接纳即释放已确认，U05 人工生产与 U08 同任务接续沿已实现基线适配，首版明确不做跨任务/跨普通-drain 目的留场复用和早到完工自动补绑，不留启用分支；U01～U08 不再列业务未决，非离场正常结果沿现有读口，B1/B7 仅补身份正确、终位明确的目标/面向不符架位置，U06 为实现验收；不自动实现、提交、迁移运行库、部署或访问现场。
- 一个组件、原业务 owner/一个 progression；不新增组件业务码、Sender、调度器或私有通知。
- 不新增组件/宿主手工锁、资源占位控制、通道租约、协调版本锁或容量账；平台原事务/幂等/结果校验/派发保护保持。
- 原事件、请求、命令、Transport、字节/路由/附录/期限/历史 None 不改写；源码合并不是原记录归属迁移。
- 通知只携带原业务码，after_commit/外层事务、1 秒连接预算/无发布重试与 5 秒同入口 Beat 保持。
- 并发/恢复按[设计 §7.1～7.3](../specs/2026-10-30-bin-roller-capability-design.md#roller-recovery-walkthrough)：同事务保证原消费/后继/意图一起提交，真实经过/段/回架批次/架动作及实际业务输入/原意图的必要唯一约束使不同 work 复用原记录；队首只作本次输入快照、登记后原请求不随换头重建；无 ACTIVE 不等于无历史，已完历史不作当前门禁；U06 删除不足以覆盖跨决策窗口的请求级待决唯一补丁，仅进入架流/正常求架的原宿主单条独立 advance 整笔 SERIALIZABLE，按设计 §7.1 覆盖判定/登记/消费；原 40001 新会话整事务重试包含 commit，提交未知沿原 work 完整 SERIALIZABLE 推进，查空不证明回滚/不授权首登，原业务判定/唯一性/集合依赖及最终提交校验登记；不升 receiver/短扫描/已有无关纯生产/其他业务，不改共享引擎或连接池，不新增隔离选择器/锁/协调状态/执行器；删除本线所有未收口 drain 的排他索引，本点经过按原分隔依据识别，旧状态不拒绝新到位、A→B→A 不合并，原 Result 不重复分隔；删除通用父后继登记及本点前驱条件更新，不将 FIFO 箱用作求架协调节点，不新增平台接口；收据清理保留技术摘要到原经过的映射，重启读取原引用/冻结输入，不重新委托/改挂任务。B1～B5/B7 验证同一实际业务输入只登记一个原意图、等价扫码冲突读回、重复/竞争、外层回滚及提交不明，跨决策消费窗口的旧快照首登须验证 SERIALIZABLE 串行等价、commit 时失败/未知、原身份恢复和关闭后的隔离不泄漏；U06 设计按此收口并进入可编码基线，未知提交先查空/旧事务随后完成及重启等列入实现验收，不再拆后续微审查；软件测试未做仍不算通过；未提交的经过归属沿原 receiver/U02 重报验证，不增“经过待核对”中间态或时钟证明；删除固定 FIRST/查链尾/请求来源协调链，保留真实原求值/执行进度查询，B6 不新增恢复设施。
- 新产品验收与历史框架验收分开；fixture 不入生产 catalog，正式模型/迁移同步加载并保持单一 Alembic head。

## Review Focus

1. 四点只有 bin_roller 一个输入目标，生产业务不再注册 SCAN2；业务拒绝不吞事实，存储失败仍走原回滚/重报——B2/B7。
2. SCAN2 成功委托即结束组件受理项；生产准入/WAIT/完工及释放决定唯一归业务，组件只执行原命令与消费原结果，不再等一份生产状态——B2/B7。
3. 原事实、当前位置与原履约分别保存；CTU03 接纳即收 WES 原周期、不等最终位置；旧终态只补历史、不清新架——B1/B5。
4. 按[正常场景推演](../specs/2026-10-30-bin-roller-capability-design.md#roller-normal-walkthrough)核对原动作及计数；普通/纯回收共用 CTU01/逐面服务/CTU02/CTU03；同任务当前同面新服务不重复架动作，异面才换面。回箱非空 1～4 箱即求值，无候选不等于排空——B3～B5。
5. 正常回流按 return_batch FIFO 执行，人工移出由独立 TODO 维护端点剔除对应队列记录；B6 只核对边界，不新增异常批次/平台派发改造或启用前置。

## 文件与启用门槛

组件代码集中在 app/businesses/_components/bin_roller/，原平台仅保留 U07 已明确的必要读口/通知适配；feed_flow/return_flow/rack_flow 均为内部方法；任务入口仍为原业务。生产适配放实际业务 roller_ports.py，任务/计划/取消继续由业务原入口受理，规范化供箱变化在同事务交给组件。SCAN2 生产回调不拥有 receiver 或第二放行发送器；本线本点事件流划分经过，技术旧身份重报不切分；每经过的已提交委托不在恢复阶段重做，迟到旧完成只关联原命令。物理/RCS 互斥及 ECS Result 推进直接作为约束，不增排序器或过期 SCAN2 派发状态机；在制段取消后按实际到位继续请求 WMS。两类架的 CTU01/02/03 只在一个 rack_flow 方法实现；service 消费本次 FEED/RETURN_BATCH 等原结果后同事务进入它，准备下一原步骤/首个 Outbox 意图，不以另一种 work 或 Beat 作本地交接前置。DRAIN 只管理供架/周期引用，首次求架由未承接 FIFO 发现，不要求先有架周期。

已确认规则、U04 已验证源码适配、U05 人工准入/完工与 U08 同任务接续适配、U07 CTU03 接纳释放/非离场读口、U06 并发实现，以及四点附录/配置、真实完整生产业务分别核验；B6 仅核对 FIFO 与独立人工移出 TODO 的边界。内部测试可注入确认合同，不注册假业务或空附录；B1/B7 复用正常 outcome/member_facts，仅为目标/面向不符的明确架位置补原快照/通知；不复制 pending。B6 不新增运行模块或平台派发改造，人工实际移出确认后剔除该次队列记录，其余按正常 FIFO 继续；维护端点独立 TODO 不作为启用前置。组件不直查框架表；原业务按每类本轮 ID 上界与游标轮换分页，不让等待前页阻塞后续待办。当前只有 coarse_sorting 生产包，完整人工生产包是 B7 正式接入的外部交付依赖，不能用测试适配器或空壳宣告完成。 首版只要求首个真实业务正式接入，两种适配器/owner 的复用验证在测试环境完成，不要求四类生产包齐备。生产任务完成不以组件全局 FIFO 排空或全部货架离场为统一前提。
