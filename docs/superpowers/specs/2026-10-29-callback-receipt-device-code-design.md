# 回调收据设备检索设计

## 范围与数据来源

按用户要求，在共享 `callback_receipt` 表增加可空 `device_code`，便于按设备检索。ECS Event 从校验后的信封设备码写入，ECS Result 从已关联原命令的校验后结果写入；WMS 收据无设备信封，保持 NULL。无效回调和不存在原命令的 Result 沿用原策略，不新增收据。

该字段是收据上的原始设备码快照，不关联设备表外键，不参与摘要、幂等、授权或路由。重报不更新原行，历史收据保持 NULL，不从诊断片段、当前绑定或可能截断的快照猜测回填。

## 存储与检索

使用 nullable Text，保留现有长设备码能力，不截断、不新增长度上限。PostgreSQL 建 `callback_receipt_device_idx` 哈希索引，用于 `WHERE device_code = ...` 等值检索，避免长设备码触发 B-tree 键大小限制；SQLite 使用普通索引。

新持久文本必须为可编码的 UTF-8 且不含 NUL，ECS Event 在原收据优先查重之后、新建收据之前拒绝不满足该约束的设备码，保证返回协议错误而非数据库异常；不修剪或改写有效值。该限制不影响历史原样重报的既有响应。ECS Result 沿用已有设备码校验及原命令匹配。

现有 `GET /api/v1/dev/ecs/events/{digest}` 的 receipt 返回 `device_code`，历史行返回 null；不新增列表、管理页面或检索接口。直接设备等值查询可使用上述索引。

## 迁移与验收

增加一条从当前 `d7cf20261029` 延伸的迁移，保留唯一 head；旧行原字段、响应和身份保持不变，新增列为 NULL。有非空 device_code 的收据时禁止删除该列的降级；只有新字段均为 NULL 才允许降级，保留原行。

验证 ECS Event/Result 写入、重报原值、WMS NULL、摘要查询、长码等值检索、无效文本拒绝，以及 SQLite/PostgreSQL 的保留数据升级与降级保护。沿用 MOCK 和内部验证，不连接现场，不提交、推送或部署；保留当前扫码字段实现和文档/P3 修改及暂存状态。
