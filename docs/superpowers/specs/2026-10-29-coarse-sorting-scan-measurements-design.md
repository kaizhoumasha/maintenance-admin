# 粗分实际扫码测量字段设计

## 已确认范围

2026-10-29 用户提供实际 `SCAN_COMPLETED` 报文，并明确选择按实际字段同步实施；WMS 的 `reel_diameter` 使用英寸，`size_inch=7` 传原值 `7`。沿用当前功能分支，保留现有计划回填、P3 修复及暂存状态；不提交、推送或部署，不向现场发送请求。

## 唯一合同与映射

公共 ECS 信封仍为 `device_code`、`event_type`、`timestamp`、`data`，设备角色、工作线、事务、原事件摘要和去重规则不变。业务 Payload 只声明以下必填事实：

| ECS data | 类型及单位 | 既有业务事实 / WMS data |
| --- | --- | --- |
| `barcode` | string，原样保留 | `barcode` |
| `size_inch` | 有限 JSON number，英寸 | `reel_diameter`，原值，不换算 |
| `thickness_mm` | 有限 JSON number，毫米 | `reel_thickness`，原值，不换算 |

整数和小数均可；拒绝 bool、字符串及非有限数，不新增范围或精度约束。沿用 `CallbackPayload.extra="ignore"`：实际报文中的 `location`、`scan_time`、`result` 不进入业务事实，也不新增业务分支；完整原始 data 仍参与公共接收器的身份计算。持久收据保存原摘要和响应，原始 body 的诊断快照继续沿用平台采样及截断策略，不承诺额外元数据完整持久保存。事件时间继续采用外层 `timestamp`。

受理时显式将测量值映射为既有持久业务事实字段，后续 WMS 请求及待办推进不改格式。这样已受理待办不需要迁移或运行时兼容分支。新公共 ECS 输入只使用 `size_inch`、`thickness_mm`，不提供旧字段别名；原始收据、历史身份和冻结请求不改写或重放。

## 方案选择

采用用户已选择的“以实际报文字段为准”：修改现有唯一处理器的 Payload，在受理边界做两项显式映射，Swagger 样例同步实际报文形状。保留 WMS 字段名及业务持久事实，改动最少。

不增加两套公共字段、另一套处理器或新数据库列；不将英寸换算为毫米。直接重命名持久事实会破坏既有待办，因此保留其格式。这是实现选择，不表示用户新增了其他业务要求。

## 验收

- 实际完整报文经公共回调可靠受理，额外元数据不进入业务事实；原条码、外层事件时间及完整事件身份保留。
- 接受整数或小数测量值，缺字段、bool、字符串及非有限数被拒绝。
- 业务重建后，既有格式的待办仍向 MOCK WMS 发送 `reel_diameter=7`、`reel_thickness=15.3`，且不附加设备元数据或 data 内时间字段。
- 公开调试入口和 Swagger 从同一模型生成新样例；完成原 MOVE_FORWARD/Result 闭环仍止于等待箱格分配。
- 原双机部署及其证据为历史基线；本轮只按 MOCK、内部验证验收，不更新服务器制品或宣称现场通过。
